# L2 题目讲解（解题老师）· 需求细化

> 对应一页纸里的 **L2**。
> 三种给题方式都要支持：粘贴文字、上传 PDF/Word/PPTX、拍照/截图。
> 目标不是「给一个答案」，而是「讲明白，下次遇到同类题会做」。

---

## 1. 用户与情境

大二学生写作业、复习时遇到不会的题，手边可能是：

- 电子版作业（PDF / Word / PPTX）
- 网页或文档里的文字题
- 纸质习题册、PPT 上的一道题（拍照/截图）

用户想要的是**老师式的讲解**：先提示、再分步、最后给答案，而不是甩一个结果。

## 2. 三种输入怎么处理

| 输入方式 | 处理 | 用户看到 | 是否进课程知识库 |
|---|---|---|---|
| 粘贴文字 | 直接作为题干；保留公式的 LaTeX 写法 | 原样文本 | 否 |
| 上传 PDF/Word/PPTX | 提取文字；若一页多题，让用户选中一题 | 可编辑的题干 | 否 |
| 拍照/截图 | 视觉模型转写：文字 + 公式转 LaTeX；**不做解答** | 左边原图、右边可编辑题干 | 否 |

**硬规则**

1. **先转写、再确认、后讲解**：转写结果必须让用户确认或修改，确认后才进入讲解。否则 OCR 错一个符号，整道题讲错。
2. **第一版只保证印刷体**：拍照主要针对教材/PPT/打印作业；手写体尽力而为，置信度低时提示「请核对或直接改文字」。
3. **扫描版 PDF**（没有文字层）不单独做 OCR，提示用户「截图或拍照上传」。
4. 题目图片**不进 Chroma、不进课程资料库**，避免污染 RAG；按用户隔离存储，可删除。
5. 图片中的姓名、学号不写进日志。

## 3. 讲解流程（默认引导式）

```
收到题目
  → 转写 + 用户确认
  → 判断课程 / 题型 / 知识点（3–5 个关键词）
  → 用关键词检索本地课程资料 top-4
      ├─ 命中：先给 1 个思路提示，问「你卡在哪一步？」
      │     → 用户说「继续」：给下一步
      │     → 用户说「没思路」：给更具体的提示
      │     → 用户说「直接看答案」：给完整解答
      └─ 不足：联网检索，标 [W]，再按上面流程讲
  → 完整解答后：总结方法 + 1 个易错点
```

**讲解规则**

- 默认**先提示、后步骤、最后答案**；用户明确说「直接给答案」才跳过提示。
- 每一步都标「这一步用了哪个知识点」，不能只写算式。
- 本地资料与网络冲突时，**以课程资料为准**，并说明差异（考试按老师讲的）。
- 本地资料不足才联网；「不足」的判定：top-4 相似度都低于阈值，或模型明确判断资料无法支撑回答。
- 不确定就明说「这题我不确定」，给验证方法，不硬编。

## 4. 固定输出格式

完整解答必须按这个结构输出，方便阅读，也方便评测：

```
【课程】算法设计与分析
【题型】计算 / 设计
【知识点】动态规划；0-1 背包；状态转移方程
【思路】定义 f[i][j] 为「前 i 件物品、容量 j」的最大价值；每件物品只有选或不选两种决策
【步骤】
  1. 状态：f[i][j]
  2. 不选第 i 件：f[i-1][j]
  3. 选第 i 件：f[i-1][j-w[i]] + v[i]（j >= w[i]）
  4. 两者取最大；边界 f[0][j] = 0
  5. 答案：f[n][W]
【答案】按上述转移填表，f[n][W] 即最大价值
【依据】[L1] ch03 动态规划 第 12 张幻灯片
【易错点】一维数组优化时 j 要倒序；忘记「不选」的情况
```

公式用 LaTeX，代码用代码块；没有依据的部分写「推断」，不要伪装成资料原文。

## 5. 成功标准

### 5.1 三种输入

| 指标 | 目标 |
|---|---|
| 粘贴文字转写 | 100% 原样 |
| PDF/Word/PPTX 提取 | ≥ 95%（文字版） |
| 印刷体拍照转写 | ≥ 90%（公式符号可接受个别错，但必须让用户改） |
| 转写确认流程 | 10/10 次都先确认再讲 |

### 5.2 讲解质量（固定 10 道题：8 道资料内、2 道资料外）

| 指标 | 目标 |
|---|---|
| 最终答案正确 | 8/10（目标 9/10） |
| 知识点标注 | 10/10 |
| 资料内引用正确 | 8/8 |
| 编造（资料没有却说有） | 0 次 |
| 首轮只给提示、不直接给答案 | 10/10 |
| 用户说「直接看答案」时切换 | 10/10 |
| 资料外 2 题明确说「本地没有」 | 2/2 |

### 5.3 体验与成本

| 指标 | 目标 |
|---|---|
| 拍照转写耗时 | < 8 秒 |
| 确认后首字延迟 | < 5 秒 |
| 单题成本（含拍照） | ≤ 0.15 元 |
| 拍照配额 | ≤ 3 张/人/天，按 2 轮对话计入 20 轮配额 |

## 6. 边界

- ❌ 不接「整套作业/整张卷子」批量代做；一次只讲一题，可以连续问
- ❌ 不替考、不提供考场作弊方案
- ❌ 不保证手写体转写；转写不确定时必须提示用户核对
- ❌ 计算题数值要用 calculator 复核，不能只靠模型心算
- ❌ 证明题不允许「显然」「易得」式跳步
- ❌ 题目图片不入课程库、不跨用户可见、可删除
- ❌ 图片里的姓名/学号不写日志

## 7. 对工期和预算的影响

| 项目 | 变化 |
|---|---|
| 视觉转写接入（第三方视觉模型） | +3–4h（W3） |
| 题目表 + 上传/确认接口 | +2–3h（W3） |
| 引导式讲解提示词 | +2–3h（W4） |
| 前端「上传/确认/提示/看答案」 | +3–4h（W5） |
| 评测用例扩充 | +2h（W7） |
| **合计** | **L2 相关约 +12–16h**；后续推送、PPTX 等又增加约 2h，大纲当前总工时 **131h** |

**预算**

- 视觉模型只做「转写」，不做讲解；讲解仍由 DeepSeek 完成。
- 视觉模型单价按约 0.02–0.05 元/张估算，10 人 × 3 张/天 × 30 天 ≈ 18–45 元/月。
- 加上文字对话约 150 元/月，总成本接近 200 元上限，所以拍照配额必须卡住。

**降级方案**

- 没配置视觉模型 Key 时：拍照入口提示「暂不可用」，粘贴和 PDF/Word/PPTX 正常。
- 这样 W3 可以先交付文字/PDF 版本，拍照在 W3 后半段补上。
