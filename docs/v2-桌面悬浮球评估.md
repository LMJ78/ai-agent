# v2 评估：桌面悬浮球 + 番茄钟

> 结论先放前面：**这不是给现有 Web 应用加一个按钮，而是多做一个桌面客户端。**
> MVP 大约 **60–85 小时**，按每周 15 小时算要 **4–6 周**；放进现在的 8 周计划，会把总工时从 122h 推到 190h 左右。

---

## 1. 为什么必须单独做客户端

Streamlit 页面做不到这些：

- 窗口永远置顶、无边框、半透明、圆形
- 系统托盘图标、开机自启
- 关掉浏览器后还在运行
- 到点弹 Windows 通知

所以「悬浮球」一定是一个跑在本机的程序，通过 HTTPS 调你的 FastAPI。Web 端继续负责聊天、资料、题目；桌面端只负责「计时 + 提醒 + 看进度」。

## 2. 四种实现路线

| 方案 | 技术 | 预估工时 | 优点 | 缺点 |
|---|---|---|---|---|
| **A. Tkinter** | Python 内置 | 35–50h | 零依赖、打包小、上手快 | 界面朴素；透明边缘有锯齿；圆角/阴影难做 |
| **B. PySide6** | Qt for Python | 50–70h | 真正的圆角/半透明/托盘；好看 | 包大（约 80–150MB）；要学 Qt 信号槽 |
| **C. Electron** | Node + HTML | 80–120h | Web 技术、UI 最自由 | 新开一套技术栈；包 150MB+；对 8 周项目太重 |
| **D. Document PiP** | 浏览器 API | 10–15h | 零安装、能置顶、复用现有前端 | 只有 Chrome/Edge 支持；浏览器必须开着；是矩形小窗，不是球 |

**建议**：如果要做「真球」，选 **B. PySide6**；如果只是想 demo 里有个置顶小窗，选 **D**，但它不满足「桌面悬浮球」的定义。

## 3. MVP 功能（先砍到这些）

1. **悬浮球**：置顶、可拖动、单击展开面板、右键退出
2. **番茄钟**：25 分钟专注 / 5 分钟休息，开始、暂停、重置，结束弹通知
3. **待办提醒**：每 60 秒拉一次后端，到点弹 Windows 通知 + 球上红点
4. **登录一次**：token 存 Windows 凭据（`keyring`），不用每次输密码
5. **今日进度**：今天专注了多少分钟 / 目标完成百分比
6. **托盘 + 开机自启**（可选，但很影响「每天用」）

先不做：多平台、自动更新、代码签名、复杂统计图表、Agent 直接控制计时器。

## 4. 工作量拆分

### 4.1 后端（FastAPI + SQLite）

| 任务 | 工时 |
|---|---|
| `todos` 加 `remind_at` / `reminded_at`，到期查询接口 | 5–7h |
| `study_sessions` 表 + 番茄钟开始/完成接口 | 3–4h |
| `goals` 表 + 今日目标进度接口 | 4–6h |
| 测试（到期、重复提醒、越权、时区） | 4–6h |
| **小计** | **16–23h** |

### 4.2 桌面客户端（PySide6）

| 任务 | 工时 |
|---|---|
| 学 PySide6 基础 + 项目骨架 | 6–8h |
| 无边框置顶球：拖动、点击、右键菜单 | 8–12h |
| 番茄钟状态机 + 通知 + 声音 | 6–8h |
| 登录 + token 存 `keyring` | 3–4h |
| 轮询提醒 + toast + 红点 | 5–7h |
| 托盘图标 + 开机自启 + 设置 | 5–7h |
| PyInstaller 打包 + 干净机器测试 | 6–8h |
| **小计** | **39–54h** |

### 4.3 联调、文档、评测

**6–10h**

### 4.4 总计

**约 61–87h**，按 **70–85h** 做计划比较稳。这还没算「提醒必须在客户端关闭时也生效」——那要加后台服务或计划任务，再 +10–15h。

## 5. 架构与数据

```
桌面客户端（PySide6）                  Web 端（Streamlit）
├─ 悬浮球 / 番茄钟                    ├─ 聊天 / 资料 / 题目
├─ 托盘 / 通知                        └─ 目标设置
├─ 每 60s 拉一次提醒
└─ token 存 keyring
        │ HTTPS + JWT
        ▼
FastAPI
├─ /api/reminders/due      到期提醒
├─ /api/pomodoro/sessions  专注记录
├─ /api/goals              学习目标
└─ /api/todos              待办
        │
      SQLite
```

新增/修改的表：

| 表 | 字段 | 说明 |
|---|---|---|
| `todos` | `remind_at`, `reminded_at` | 什么时候提醒、是否已提醒 |
| `goals` | `title`, `target_minutes`, `period`, `start_date`, `end_date`, `status` | 每日/每周目标 |
| `study_sessions` | `goal_id`, `todo_id`, `started_at`, `ended_at`, `duration_min`, `completed` | 番茄钟记录 |

**提醒机制**：客户端每 60 秒 `GET /api/reminders/due`，后端返回「到点且未提醒」的待办并标记 `reminded_at`。10 个人用，轮询足够，不需要 WebSocket。

**番茄钟**：计时在客户端本地跑，完成时才 `POST /api/pomodoro/sessions` 落库；服务端不维护倒计时状态，简单可靠。

## 6. 对 8 周计划的影响

当前计划 **122h / 8 周**，周均 15–16h。

| 方案 | 总工时 | 需要周均 | 结论 |
|---|---|---|---|
| 8 周核心 + 桌面端 v2 | 122h + 75h | 分 13 周，约 15h | **推荐** |
| 12 周一起做 | 197h | 约 16.5h | 可行，但要多 4 周 |
| 8 周硬塞 | 197h | 约 24.6h | 有课的情况下不现实 |
| 砍核心换桌面端 | 约 170h | 约 21h | 砍掉拍照/网络/生活功能也不够 |

**砍核心救不了**：拍照 12–16h、网络 4h、生活简化 6h、评测缩减 3h，全砍也只有 25h，离 75h 差很远。

## 7. 风险

| 风险 | 说明 | 对策 |
|---|---|---|
| 10 个同学都要装 | 分发、更新、杀软误报 | 只给你自己和 2–3 个愿意折腾的同学装；其余用 Web |
| 只支持 Windows | 同学用 Mac 就用不了 | 先声明 Windows 10/11；Mac 放 v3 |
| 杀软误报 | PyInstaller 单文件常被拦 | 用 onedir 打包；附说明；不追求代码签名 |
| 关掉客户端就没提醒 | 轮询依赖进程活着 | 开机自启 + 托盘常驻；接受「关了就没了」 |
| token 泄露 | 本机文件被读 | `keyring` 存 token；HTTPS；支持退出登录 |
| 多显示器 / 高 DPI | 球跑到屏幕外、模糊 | 记住上次坐标；启动时做屏幕边界检查 |
| 范围膨胀 | 想做统计图、成就、白噪音 | 全部进 v2.1，不在 MVP |

## 8. 建议路线

1. **现在到 W8**：按 122h 计划把 Web 核心做完（三种给题、解题老师、生活模式、多用户、上线）。
2. **W9–W12**：桌面端 MVP（PySide6），只做「球 + 番茄钟 + 到期提醒 + 今日进度」。
3. **W13**：打包、内测、写文档；愿意折腾的同学再装。
4. 如果 W7 想先给演示加一个「置顶计时器」的视觉效果，用 Document PiP 做 8–12h 的临时版，但别把它当最终形态。

## 9. 需要你定的问题

1. 要**真正的球**（透明、圆角、托盘常驻），还是浏览器置顶小窗就够？
2. 只做 **Windows** 可以吗？
3. 提醒必须在**客户端关闭时也生效**吗？（要加后台服务/计划任务，+10–15h）
4. 10 个同学都装客户端，还是只你自己 + 2–3 个人？
5. 番茄钟数据要不要让 Agent 能查（「今天学了多久」）？这会影响提示词和工具设计。
6. 能接受 PyInstaller 的杀软误报和「无代码签名」吗？
