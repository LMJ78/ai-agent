# V3 优化方案：网页 UI + 用户知识库 + 题目归档

> 状态：方案稿，待确认；先不动现有代码。  
> 目标：把当前 Streamlit 原型升级成更像 DeepSeek 网页版的正式前端，并把已有 RAG 和题目图片真正用起来。

## 0. 一句话结论

**UI 是主工程，RAG 和题目历史是“补前端 + 少量后端”。**

- 真正网页 UI：建议从 Streamlit 迁到 **React + Vite + TypeScript + Tailwind**，FastAPI 后端保留。
- 用户知识库：后端 `/api/documents` 和 BM25 已经存在，主要补“知识库”页面、状态/块数、删除/重建。
- 题目图片：数据库和文件其实已经保存了，缺的是**图片读取接口 + 题库页面**，不用重做存储。

## 1. 现状判断

### 已经有的

- FastAPI + JWT 登录、用户隔离、邀请码。
- 聊天 SSE、工具循环、学习/生活两种模式、教学三阶段。
- 本地 RAG：PDF/PPTX/DOCX/MD/TXT 解析、切块、BM25、`search_notes`。
- 题目表 `questions`：题干、科目、章节、来源、原文件路径、草稿/确认状态。
- 文档表 `documents` / `chunks`：用户自己的课件已经按 `user_id` 隔离。
- Streamlit 单文件 UI：登录、聊天、历史、录题、待办、记忆、推送。

### 缺的

- Streamlit 的 DOM/布局受限，做不出真正的侧边栏 + 主内容区 + 顶栏模式切换。
- 没有“知识库”页面；`/api/documents` 只有接口，前端没用起来。
- 没有题目图片读取接口；题目列表也没有按科目浏览的页面。
- 历史会话目前只是简单列表，没有按科目、日期分组。

## 2. 前端路线选择

| 路线 | 做法 | 工时 | 结果 |
|---|---|---|---|
| A. Streamlit 美化 | 注入 CSS、调布局、换主题 | 18–28h | 颜色和间距会好一点，但仍是 Streamlit 结构，达不到“真正网页” |
| **B. React SPA（推荐）** | 新 `web/` 前端，FastAPI 只做 API | **MVP 70–95h** | 可做出 DeepSeek 式侧边栏、模式切换、主题、题库/知识库 |
| C. Next.js | React + SSR/路由 | 85–120h | 对 10 人项目过重，登录和部署更复杂 |

**推荐 B，不建议把 A 当最终方案。**  
A 可以作为过渡：React 没做完前，旧 Streamlit 继续能用。

技术栈建议：

- React 18 + Vite + TypeScript
- Tailwind CSS + shadcn/ui（按钮、弹窗、下拉、Toast 直接用）
- `react-router-dom` 路由
- `react-markdown` + `remark-gfm` + `remark-math` + `rehype-katex`（公式）
- `lucide-react` 图标
- SSE 用原生 `fetch` + `ReadableStream`，不引额外大库
- 登录 token 放 `localStorage`，请求统一带 `Authorization: Bearer`
- FastAPI 加 CORS；生产环境把 `web/dist` 交给 FastAPI 静态托管，或 Nginx 托管

## 3. 新前端信息架构

```text
┌──────────────────┬──────────────────────────────────────────┐
│  伴学             │  当前科目 / 会话标题        [学习|生活]  │
│  + 新对话         │                                          │
│  搜索会话         │          对话区（居中 760–820px）         │
│                  │                                          │
│  科目分组          │   用户消息 / 助手消息 / 引用 [L1]         │
│   ▸ 算法设计与分析 │   工具步骤（可折叠）                      │
│   ▸ 高等数学       │                                          │
│   ▸ 未分类         │  ┌────────────────────────────────────┐  │
│                  │  │ 输入框  拍照/上传  发送              │  │
│  知识库            │  └────────────────────────────────────┘  │
│  题库              │                                          │
│  待办 / 记忆       │                                          │
│  推送设置          │                                          │
│  ─────────        │                                          │
│  用户 / 退出       │                                          │
└──────────────────┴──────────────────────────────────────────┘
```

### 侧边栏

- 顶部：Logo、`+ 新对话`、搜索框。
- 会话按 **科目 → 时间（今天/7 天内/更早）** 分组，可折叠。
- 每个会话显示标题、最后更新时间；右键/更多菜单：重命名、删除。
- 科目分组旁边显示会话数量；支持“只看某科”。
- 底部固定：知识库、题库、待办、记忆、推送设置、退出。

### 顶栏

- 左侧：当前科目 / 会话标题。
- 右侧：**学习模式 / 生活模式切换**，一个 segmented control。
- 学习模式：蓝紫色强调色、引用卡片明显、显示教学阶段（提示/下一步/答案）。
- 生活模式：暖橙/玫红强调色、气泡更柔和、显示记忆/情绪标签，弱化“课程”元素。
- 两套主题用 CSS 变量切换，不复制两套页面。

### 聊天区

- 消息居中，最大宽度约 800px。
- Markdown、代码高亮、LaTeX 公式。
- `[L1]` / `[W1]` 渲染成可点击引用 chip，右侧/底部弹出处来源。
- 助手消息底部：复制、重新生成、（学习模式）继续/看答案。
- 流式输出时显示光标和“正在思考/正在查课件”状态。

## 4. 三项需求怎么落地

### 4.1 网页 UI（最大工程）

**要做：**

1. `web/` 新 React 工程，路由：`/login`、`/chat/:id?`、`/knowledge`、`/questions`、`/todos`、`/memories`、`/settings`。
2. 登录/注册页，接现有 `/api/auth/*`；401 自动回登录。
3. 主布局：侧边栏 + 顶栏 + 内容区；移动端侧边栏变抽屉。
4. 会话列表按科目/日期分组；搜索、重命名、删除。
5. 聊天页接 SSE，保留现有 `teaching_stage`、`question_id`、`course` 参数。
6. 两套模式主题；切换后当前会话不变，只换配色/文案/功能侧重。
7. 旧 Streamlit 先保留，React 稳定后再下线。

**不做（这一版）：**

- 不做 SSR、不做多端 App、不做复杂动画。
- 不做完整的 Markdown 富文本编辑器。

### 4.2 用户自上传课件的 RAG 知识库

**先说明：RAG 不是从零做。** 后端已经有 `documents`、`chunks`、`search_notes`、BM25，只缺用户入口和状态管理。

**知识库页面：**

- 选择科目/章节，拖拽或点选上传：PDF / PPTX / DOCX / MD / TXT。
- 上传后显示：文件名、大小、状态（处理中/就绪/失败）、块数、时间。
- 按科目分组；支持删除、重新导入。
- 失败时显示原因（例如扫描版 PDF 没有文字层）。
- 上传成功后给一个“用这份资料提问”的按钮，跳到聊天并带上科目。

**后端小改：**

- `GET /api/documents` 返回 `chunk_count`、`status`、`error_message`。
- `POST /api/documents` 继续同步入库（MVP 够用）；前端显示 loading。
- 文件去重可选：按文件 hash 防止重复上传。
- 删除文档时同时删 chunks 和上传副本（已有逻辑，补测试）。
- 引用来源：沿用 `[L]`，前端展示文件名/位置。

**边界：**

- 扫描版 PDF 当前解析不了；要支持得加 OCR，另算 8–12h。
- 这版仍是 BM25，不加向量模型；语义检索以后再说（约 +15–25h）。

### 4.3 题目图片历史与按学科归档

**先说明：题目其实已经存了。** `questions` 表有 `source_path`，上传文件在 `data/uploads/questions/{user_id}/`；现在缺的是展示。

**题库页面：**

- 按科目/章节筛选，卡片或列表显示：
  - 题目缩略图（图片题）或文件图标（PDF/Word）
  - 题干前两行、来源、时间、状态（草稿/已确认）
- 点开详情：原图/原文件、完整题干、确认/修改、删除。
- 操作：
  - “再讲一遍”：带 `question_id` 跳聊天。
  - “查看原图”：弹窗/新标签。
  - “按科目归档”：按 course 分组统计。
- 支持按时间、来源类型（拍照/PDF/文字）筛选。

**后端小改：**

- 新增 `GET /api/questions/{id}/file`：校验 user_id，返回图片/PDF；不暴露静态目录。
- `GET /api/questions` 增加 `offset`、`source_type`、`status` 参数；返回 `has_image`、`original_filename`。
- 可选：上传时生成 320px 缩略图，列表更快。
- 删除会话时题目要保留：`Question.session_id` 改为可空 + `ON DELETE SET NULL`，避免归档被会话删除影响。

## 8. 风险与取舍

1. **React 学习成本**：这是最大不确定项；如果完全不熟，先花 3–5 天做一个小页面练手。
2. **Streamlit 与 React 并存**：迁移期两套 UI 会增加维护；建议 MVP 完成后尽快下线 Streamlit。
3. **扫描版 PDF**：当前不支持；要做 OCR 会明显增加成本。
4. **向量检索**：现在 BM25 够用；不要一上来就上 embedding，先保证上传/引用/删除闭环。
5. **部署**：10 人使用不需要 K8s/Redis/Celery；FastAPI + SQLite + 单机静态前端足够。
6. **安全**：之前泄露的视觉 Key 要轮换；`.env` 永远不进 Git。

## 9. 需要你确认

1. 走 **B（React 重写）**，还是先 **A（Streamlit 美化）**？
2. 前端用 **React** 还是你更熟的 Vue？
3. MVP 是否就按“聊天 + 历史 + 知识库 + 题库”四块，待办/记忆/推送晚一点迁移？
4. 扫描版 PDF 的 OCR 这版要不要？不要的话，UI 明确提示“请上传文字版”。
5. 学习模式用蓝紫、生活模式用暖橙，是否 OK？要不要再做深色模式？

确认后我建议先做 **P0 静态原型（3–5h）**，你看布局满意再开始写正式代码。
